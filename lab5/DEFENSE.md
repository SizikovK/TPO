# Демонстрация лабораторной №5 преподавателю

Открой два терминала. Команды рассчитаны на существующее окружение `lab5/.venv` и локальный образ OpenBMC. Эти файлы исключены из Git: на текущем компьютере они есть, но после клонирования репозитория на другой компьютер их нужно подготовить отдельно.

Если окружение Python отсутствует, из каталога TPO выполни:

```bash
python3 -m venv lab5/.venv
lab5/.venv/bin/python -m pip install -r lab5/requirements.txt
```

Для запуска стенда необходимы `qemu-system-arm`, `ipmitool` и образ `investigation/romulus-20250902/image.static.mtd`. Не заменяй его другим образом, ожидая точно таких же результатов.

## 1. Запуск OpenBMC — первый терминал

```bash
cd /home/kathlyju/VSCODEEEEE/study/TPO
bash lab3/start-bmc.sh
```

Дождись загрузки — появления `romulus login:`. Этот терминал оставь открытым. Если QEMU уже запущен с этими портами, второй экземпляр запускать не нужно.

## 2. Проверка доступности API — второй терминал

```bash
cd /home/kathlyju/VSCODEEEEE/study/TPO
curl --noproxy '*' -k -u root:0penBmc \
  -w '\nHTTP %{http_code}\n' \
  https://127.0.0.1:3443/redfish/v1/
```

Ожидается JSON и `HTTP 200`. Если соединение пока не устанавливается, дождись готовности сервисов BMC и повтори запрос.

## 3. Запуск всех пяти тестов

```bash
lab5/.venv/bin/python -m pytest lab5/test_redfish.py \
  -v -ra --tb=short \
  --junitxml=lab5/results/assignment-check.xml
```

Зафиксированный результат текущего стенда: **2 failed, 1 passed, 2 skipped**. Тест питания опрашивает состояние On в течение примерно 60 секунд; время HTTP-запросов может увеличить длительность. Перед повторным полным прогоном перезапусти QEMU, чтобы вернуть исходное состояние Off.

Объяснение результатов преподавателю:

- Вход работает и выдаёт токен, но возвращает HTTP **201**, а методичка требует **200**. Строгое ожидание задания сохранено в тесте.
- Информация о системе успешно получается: HTTP 200, поля Status и PowerState присутствуют.
- Запрос включения возвращает HTTP **204** вместо **202**, хост не достигает On за время проверки.
- Температурных датчиков CPU в Redfish нет, поэтому две проверки пропускаются с причиной Blocked. Это отсутствие необходимого предусловия, а не успешная проверка температуры.

## 4. Отдельная демонстрация датчиков Redfish

```bash
curl --noproxy '*' -k -u root:0penBmc \
  https://127.0.0.1:3443/redfish/v1/Chassis/chassis/Thermal
```

На текущем стенде ответ содержит `"Temperatures": []`.

## 5. Отдельная демонстрация IPMI

```bash
IPMI_PASSWORD=0penBmc ipmitool -I lanplus \
  -H 127.0.0.1 -p 3623 -U root -E sensor list
```

У температурных записей текущего стенда показания `na`: измерения недоступны. Дискретные записи cpu0/cpu1 не являются числовой температурой.

## 6. Короткая демонстрация проходящего теста

```bash
lab5/.venv/bin/python -m pytest lab5/test_redfish.py \
  -v -k test_system_information
```

Ожидается **1 passed, 4 deselected** при доступном BMC.

## 7. Что показать в коде и отчёте

Открой `lab5/test_redfish.py` и `lab5/README.md`.

- Пять сценариев из задания.
- Fixture `redfish_session`: создание сессии, повторное использование токена и удаление сессии после тестов.
- Проверки HTTP-кодов, JSON, состояния питания, температурных порогов и соответствия показаний Redfish/IPMI.
- Обработку ошибок и логирование; фактические результаты в `lab5/results`.
- Ссылку на GitHub: https://github.com/SizikovK/TPO/tree/main/lab5.

## 8. Завершение демонстрации

В первом терминале нажми **Ctrl+A, затем X**, чтобы завершить QEMU. Изменения гостевой системы будут отброшены благодаря `-snapshot`.
