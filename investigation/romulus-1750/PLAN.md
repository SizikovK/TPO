# Проверка причины Off / Inactive и нового образа Romulus

Это рабочая диагностика, не дополнение к отчётам лабораторных.

## Карта решения

| Проверка | Что она различает | Дальнейшее действие |
| --- | --- | --- |
| BMC Ready, работают консоль и API | Загрузка BMC или включение управляемого хоста | При Ready исследовать цепочку питания |
| Запрос RequestedPowerTransition принимается | Ошибка команды или выполнение аппаратных действий | При принятом запросе изучить первую ошибку служб |
| Записи I²C в AVS/VRM проходят | Доступность регуляторов питания | Сопоставить адреса скрипта с деревом устройств QEMU |
| Актуальный официальный образ на том же QEMU | Особенность старого образа или ограничение модели | Если ошибка сохраняется, одной смены образа недостаточно |
| Состояние шасси стало On | Выполнение перехода питания | Отдельно проверить состояние и загрузку хоста |
| ОС управляемого хоста действительно загружена | Реальное Active или только имитация состояния | Для настоящего Active нужен управляемый хост и его связь с BMC |

## Уже установлено

- Старый образ сообщает `2.9.0-rc1` и обращается к адресам `0x70` и `0x73` на I²C-шинах 4 и 5.
- В журнале запись в эти устройства завершается ошибкой; служба `avsbus-disable@0.service` возвращает код 1.
- В дереве устройств установленного QEMU 11.1.1 для `romulus-bmc` этих адресатов нет. Дерево сохранено в `qemu-qtree.txt` из отдельного экземпляра с остановленным CPU, без старого образа.
- Найдена официальная успешная сборка Romulus № 1750 с меткой артефактов `20260926025046`. Метаданные сохранены в `build.json`.

## Порядок исправления и критерии выбора

1. Скачать новый образ отдельно; записать источник и контрольную сумму.
2. Запустить его на том же QEMU в режиме `-snapshot` на отдельных портах. Старый образ не изменять.
3. Зафиксировать версию, состояние после загрузки и результат запроса включения.
4. Если новый образ устраняет сбой — использовать его как новый стенд, отдельно повторив проверки IPMI/Redfish. Старые результаты не приписывать новой версии.
5. Если новый образ также требует отсутствующие VRM — проверить поддерживаемую конфигурацию эмуляции OpenBMC либо добавление совместимых моделей устройств и сигналов. Простое подавление ошибок скрипта не является исправлением оборудования.
6. Если цель — именно настоящая работа ОС хоста, потребуется отдельный аппаратный или совместно эмулируемый хост. Изменение D-Bus свойства вручную таким результатом не считается.

## Результат проверки 26.09.2026

Новый образ скачан и загружен на установленном QEMU 11.1.1 с прежней моделью `romulus-bmc` и RAM 256 МиБ. Для него использованы отдельные порты 3222/3443/3623 и режим `-snapshot`; старый образ не изменялся. Контрольная сумма сохранена в `SHA256SUMS`, состав пакетов — в `image.manifest`, консоль — в `console.log`.

Версия внутри нового образа:

```text
VERSION="3.1.0-dev"
VERSION_ID=3.1.0-dev-1314-gba0045363b
BUILD_ID="20260926025046"
OPENBMC_TARGET_MACHINE="romulus"
```

После загрузки BMC достиг Ready. Выполнено `obmcutil poweron`, затем проверены состояние и журнал. Скрипт `avsbus-disable.sh` в новом образе обращается к тем же адресам на шинах 4 и 5.

```text
CurrentBMCState     : xyz.openbmc_project.State.BMC.BMCState.Ready
CurrentPowerState   : xyz.openbmc_project.State.Chassis.PowerState.Off
CurrentHostState    : xyz.openbmc_project.State.Host.HostState.Off
BootProgress        : xyz.openbmc_project.State.Boot.Progress.ProgressStages.Unspecified
OperatingSystemState: xyz.openbmc_project.State.OperatingSystem.Status.OSStatus.Inactive
```

Выдержка из нового журнала:

```text
Sep 26 03:33:28 romulus systemd[1]: Starting Disable the AVS bus on the VRMs...
Sep 26 03:33:28 romulus avsbus-disable.sh[454]: Error: Write failed
Sep 26 03:33:29 romulus systemd[1]: avsbus-disable@0.service: Main process exited, code=exited, status=1/FAILURE
Sep 26 03:33:29 romulus systemd[1]: avsbus-disable@0.service: Failed with result 'exit-code'.
```

**Вывод:** одной заменой старого образа на актуальный официальный Romulus проблему исправить не удалось. Необходимые адресаты I²C отсутствуют в стандартной модели установленного QEMU; новая прошивка продолжает требовать их. Настоящая загрузка ОС управляемого сервера также не обеспечивается одной моделью BMC.

## Как исправлять дальше

### Для тестирования управления состояниями в эмуляторе

1. Работать с отдельной копией/снимком образа.
2. Определить точные модели и регистры VRM, требуемые `avsbus-disable.sh`, `avsbus-enable.sh` и `vrm-control.sh`.
3. Проверить возможность подключения совместимых PMBus/I²C-моделей QEMU на шины 4/5 по адресам 0x70/0x73. Наличие произвольной модели регулятора в `-device help` не означает совместимость с платой Romulus.
4. Смоделировать необходимую обратную связь питания (`power good`) и проверить успешное завершение целей включения шасси. Успех — отсутствие ошибки AVS/VRM и подтверждённое состояние On, а не только принятая команда.
5. Если используется специальная сборка OpenBMC с тестовыми обработчиками аппаратных операций, явно обозначать её как имитацию. Проверять реальные вызовы этих обработчиков; не подменять результат простой записью CurrentPowerState/OSStatus.

### Для настоящего состояния ОС Active

Нужен управляемый POWER-хост с прошивкой, ОС и каналами связи/уведомлений для OpenBMC: физический сервер либо совместная эмуляция хоста и BMC. После исправления питания требуется подтверждение загрузки именно ОС хоста (консоль, новый boot_id, сообщения прогресса загрузки), затем проверка состояния, которое сообщает BMC. Подавление ошибки AVS этот уровень не реализует.

Эти изменения ещё не выполнены. Исправление не заявляется: выполнены карта решения, поиск, скачивание и контрольный тест нового образа, установлена непригодность простой замены для устранения данного сбоя.

Повторить изолированный тест можно командой `bash investigation/romulus-1750/start-test.sh`. Изменения в режиме `-snapshot` не сохраняются; выход — Ctrl+A, затем X. Новый образ пока не выбран вместо стенда лабораторных.
