# Защита лабораторных №3 и №4

## №3 — суть

Тест-план определяет, что проверяем, на каком стенде, какими шагами и по каким критериям. Вариант 24: перезагрузка сервера, напряжение матплаты, IPMI и журнал ошибки. Тест-кейс содержит предусловия, шаги, ожидаемый/фактический результат и статус.

Показать таблицу в `lab3/README.md`, затем фактические результаты. Passed — проверка пройдена; Failed — ожидание не выполнено; Blocked — нет необходимого предусловия.

## Команды №3

Из каталога `TPO`, первый терминал:

```bash
bash lab3/start-bmc.sh
```

После загрузки войти `root` / `0penBmc`. В консоли BMC:

```bash
obmcutil state
```

Во втором терминале CachyOS:

```bash
ipmitool -I lanplus -H 127.0.0.1 -p 3623 -U root -a mc info
ipmitool -I lanplus -H 127.0.0.1 -p 3623 -U root -a chassis power status
ipmitool -I lanplus -H 127.0.0.1 -p 3623 -U root -a sdr type Voltage
```

В первом запросе можно один раз ввести неверный пароль и затем повторить с верным. Пустой ответ Voltage означает отсутствие датчика, а не нормальное напряжение.

Для демонстрации нового журнала ошибки в консоли BMC:

```bash
cursor=$(journalctl -b -n 1 --show-cursor --no-pager | sed -n 's/^-- cursor: //p')
obmcutil poweron
sleep 30
journalctl -b --after-cursor="$cursor" --no-pager
systemctl --failed --no-pager
obmcutil state
obmcutil poweroff
```

`poweroff` может быть отклонён во время переходного состояния. Завершить тестовый QEMU: Ctrl+A, затем X; временный снимок будет отброшен. Не отправлять reset как демонстрацию успешной перезагрузки, если хост Off/Inactive. BMC Ready означает готовность контроллера, а Inactive относится к ОС управляемого сервера.

## №4 — суть и команды

Selenium управляет настоящим браузером: находит поля и кнопки, вводит данные и проверяет результат. pytest запускает тесты и формирует отчёт. Явное ожидание ждёт нужного состояния интерфейса, а не предполагает, что страница уже загрузилась.

На свежем запущенном QEMU показать:

```bash
HEADLESS=0 lab4/.venv/bin/python -m pytest lab4/test_webui.py -v -ra
```

Для короткой демонстрации только авторизации:

```bash
HEADLESS=0 lab4/.venv/bin/python -m pytest lab4/test_webui.py -v -k 'successful_login or invalid_credentials'
```

Показать `lab4/test_webui.py`, результаты и скриншоты в `lab4/results`. Объяснить два дополнительных кейса варианта 24: напряжение и запись ошибки. Отключённая блокировка аккаунта и отсутствие датчика — ограничения предусловий. Наличие ошибок в journalctl не гарантирует их отображение в Event logs браузера.
